## Audit and boundaries

The existing `/dev` discovers static dev routes and combines them with selected ordinary routes. Its iframe bridge supplies validated fixture config and tab commands; ordinary pages retain ordinary sessions. `/dev/tournament` also calls getCurrentProfile. The common root layout calls getSeasonCatalog/getNextTournamentOverride, which use service-role Supabase queries. Those server pages and SiteChrome therefore cannot be used as an isolated sample phone entry.

`/dev-iphone` is a separate direct-render canvas. The existing simulator is unchanged apart from exporting an additive context provider that performs no messaging. The new page filters the existing server registry to the exact trip preview and sample profile descriptors. It renders GolfTripHome with the existing simulatorTripData adapter and generic mock fixture, plus DevProfilePreview/DevEditProfilePreview/DevSettingsPreview. No page implementation is copied. Shared trip tab navigation remains in the rendered component; the page menu uses the registry's tab/subsection shortcuts. Before-round, live, unsubmitted and completed scenarios reuse existing round overrides. Profile conditionals reuse the registry. No official/real source, live account, authentication, onboarding submit, saved-trip id, push scope, remote mutation callback or privileged loader is supplied.

The entry requires NODE_ENV=development and DEV_IPHONE_PREVIEW=true and rejects known hosting/CI markers. Middleware rejects disabled and unknown child routes before session refresh. It erases the marker header on every request, and sets it only for the exact enabled route. The root checks both flag and marker before returning a minimal document without season/session providers or SiteChrome. Other requests retain their existing middleware and loaders; a caller cannot supply the marker to skip them. The page independently checks the feature gate; the client canvas also renders nothing outside development. Production NODE_ENV always disables it even with the flag set.

The canvas contains links before Next navigation and allows only its known in-memory page selections; other destinations do nothing. Route-specific CSP blocks HTTP connect requests (including API/RSC prefetch), forms, frames and external image/media destinations. Only local WebSockets for development HMR are allowed. Profile Compare additionally suppresses all real list/search/compare requests inside FixtureIsolation; outside it behavior is unchanged. Sample profile form/photo/privacy callbacks use the existing sample store, never account APIs. Optional completion/cancel callbacks keep the shared edit form in the canvas rather than using its normal router navigation; existing callers retain their original behavior. Rendered screens mount after hydration to avoid the existing randomized scoring opponent's server/client mismatch. No device bezel or iframe is added: use a real iPhone viewport / Capacitor simulator for actual media queries, fixed UI, scrolling and safe areas. A wide browser remains wide; CSS cannot emulate a separate viewport without a frame.

## Running locally

1. Stop the terminal's existing server with Control+C, then run `DEV_IPHONE_PREVIEW=true npm run dev`.
2. Open `http://localhost:3001/dev-iphone` in an iPhone browser viewport, or run `DEV_IPHONE_PREVIEW=true npx cap copy ios` and open the existing iOS project in Xcode, choose an iPhone simulator and Debug, then Run. The opt-in copy selects the same URL in the WebView; default Capacitor config still selects the existing localhost root. Capacitor copy was performed locally with the flag. Physical-device localhost is not the Mac; physical-device/network setup is outside this scope.
3. The small top-right menu selects Page and Scenario. Close collapses it; Hide for screenshot removes visible controls. Tap the now-invisible top-right 44px target or press Escape to restore controls. The restore target appears on keyboard focus. Reload restores controls.

The iOS dev wrapper now contains a first build phase rejecting every non-Debug configuration, including Release/Archive, independently of the JavaScript environment or copied config. This is a deliberately non-distributable development wrapper; a release product requires a separate reviewed configuration. Android was not copied, configured or built. No API or production authentication policy was changed.
